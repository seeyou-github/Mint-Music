# 哔哩哔哩插件 412 问题全解析（作者作品列表 + 播放地址）

> 对比对象
> - 出问题的插件：`猫头猫 哔哩哔哩`（MusicFree 格式，运行在 Mint-Music 的适配层里）
> - 参照项目：`D:\Code\Flutter_PiliPlus`（Flutter）
>
> **结论先行（两个互相独立的根因，不要混为一谈）**
>
> | 现象 | 根因 | 证据 | 处置 |
> | --- | --- | --- | --- |
> | 作者作品列表频繁 412（概率性） | 走**网页 WBI 接口** `x/space/wbi/arc/search`，受网页边缘 WAF **随机采样** | 同一身份相邻 1 秒：一次 412、下一次 200 | 换 **App 接口**（PiliPlus 同款），实测 0/N |
> | **播放全部失败（必然）** | `getCookieString()` 用 `join(";")`，Cookie 头是 `a=1;b=2`（分号后**没有空格**），`playurl` 的 WAF 规则直接判为脚本 | `";"` → 412 **6/6**；`"; "` → 200 **6/6**（交替采样） | 改 `join("; ")` |
>
> 第二条是关键：PiliPlus 的 Cookie 头由 `account_mgr.dart:41` 的 `.join('; ')` 拼出——**分号后一定带空格**；插件少了这个空格，于是「列表能进、一播放就 412」。

## 一、播放 412（「所有歌曲播放失败」）

### 1.1 复现

用 Node 按 Mint-Music 的 axios 桥语义加载补丁插件，取作者作品后逐首解析播放地址：

```
[FAIL] 这就是助农的意义！… | ExClimbWuzhi→200, finger/spi→200, playurl→412, ExClimbWuzhi→200, finger/spi→200, playurl→412
[FAIL] 有人说一台苹果18的钱… | playurl→412, ExClimbWuzhi→200, finger/spi→200, playurl→412
…
成功 0 / 失败 6
```

**6/6 全挂**，且重试（换 buvid3 后重发）依然 412 —— 说明不是随机采样，而是**请求本身被规则命中**。

### 1.2 变量隔离：根因是 Cookie 头的分隔符

先排除 cookie 内容与请求头（每个变体换全新 buvid3 + 激活 + 取 buvid4）：

| 变体 | 结果 |
| --- | --- |
| A 仅 `buvid3` / 无 referer | 200 ✅ |
| B 仅 `buvid3` / 有 referer | 200 ✅ |
| C 插件现状 cookie（`buvid3;buvid4;b_nut;buvid_fp;CURRENT_FNVAL`）/ 无 referer | 200 ✅ |
| D 同 C / 有 referer | 200 ✅ |
| E 去掉 `buvid_fp` | 200 ✅ |
| F `buvid3` + referer + `app-key: android64` 等 App 头 | 200 ✅ |

**cookie 内容、referer、App 头全都不是原因**。那为什么同一套内容放进插件就 100% 412？

把插件实际发出的请求头打出来后，差异只剩一处：

```
插件发出：  cookie: buvid3=…;buvid4=…;b_nut=…;buvid_fp=…;CURRENT_FNVAL=4048
探针发出：  cookie: buvid3=…; buvid4=…; b_nut=…; buvid_fp=…; CURRENT_FNVAL=4048
                                 ↑ 少了这个空格
```

于是做交替对照（每轮都换全新身份，1 秒间隔）：

| 分隔符 | 结果 | 412 命中 |
| --- | --- | --- |
| `;`（无空格） | 412 / 412 / 412 / 412 / 412 / 412 | **6/6** |
| `; `（分号+空格） | 200 / 200 / 200 / 200 / 200 / 200 | **0/6** |

**这是确定性的**：`playurl` 接口对「Cookie 头不符合浏览器形态」直接回 412，不进入随机采样。

### 1.3 为什么 PiliPlus 从来没这个问题

`lib/utils/accounts/account_manager/account_mgr.dart:41`：

```dart
return cookies.map((cookie) => '${cookie.name}=${cookie.value}').join('; ');
```

PiliPlus 走 `Cookie` 对象 + cookieJar 序列化，**天然是 `; `**；插件手写字符串拼接，用的是 `join(";")`。一个字符之差，播放全挂。

### 1.4 为什么「列表好了、播放全挂」

- 列表（0.3.10 起）走 **App 接口**，请求里**不带任何 Cookie** → 完全不受影响。
- 播放走 **网页 `playurl`**，必须带 Cookie → 直接撞上分隔符规则。

所以现象看起来像「修好了列表、弄坏了播放」，实际是两个独立问题。

## 二、作者作品列表 412（上一轮的问题）

### 2.1 取数路径差异（决定性）

| 维度 | PiliPlus 作者主页 | 插件原版 `getArtistWorks` |
| --- | --- | --- |
| 接口 | `app.bilibili.com/x/v2/space/archive/cursor`（`lib/http/api.dart:339`） | `api.bilibili.com/x/space/wbi/arc/search` |
| 调用点 | `lib/pages/member_video/controller.dart:119` → `MemberHttp.spaceArchive` | 直接 `axios.get` |
| 鉴权 | `appkey + ts + sign`（MD5，`lib/utils/app_sign.dart`） | `w_rid`（WBI）+ `wts` + `dm_img_*` |
| Cookie | **不发**（`account_mgr.dart:59-83` 的 `isApp` 分支直接 return） | `buvid3` + `bili_ticket` |
| 分页 | `aid` 游标 | `pn` 页码、`ps=30` |
| 412 处理 | 代码里没有任何 412 分支（全仓只有 `-352` 文案） | 1.5s 冷却 + 同身份重试 |

> PiliPlus 里也保留了网页版 `searchArchive`（`lib/http/member.dart:349`），但只挂在可选路由 `/videoWeb`（`lib/router/app_pages.dart:176`），**不是作者主页的默认路径**。

### 2.2 网页接口的 412 是概率性的

同一 IP、同一身份、相邻 1 秒：

| 请求 | 结果 |
| --- | --- |
| App 接口 第 1 页 | `200 / code=0`，`count=243` |
| 网页 WBI 第 1 页 | **`HTTP 412`** |
| 网页 WBI 第 2 页 | `200 / code=0` |
| App 接口 第 1 页（第二次） | `200 / code=0` |

补 header 只能降概率、不能消除（同一形态两次采样分别出现 0/4 与 4/5）。**注意：这里的分隔符不是原因** —— 实测 `x/space/wbi/arc/search` 用 `;` 与 `; ` 各 3 次，412 命中分别是 1/3 与 2/3，没有区别。列表接口是采样，播放接口才是格式校验。

### 2.3 App 接口的分页语义（迁移时必须知道）

| 传参 | 结果 |
| --- | --- |
| `pn=2` | 与第 1 页完全重复 20/20 → `pn` 被忽略 |
| `next=<上一页 next_cursor>` | 仍然重复 20/20 → `next_cursor` 不能当 `next` 用 |
| `aid=<上一页最后一条 param>` | 19 条，**重复 0** → 唯一有效游标 |
| `ps=30` | 仍返回 20 条 → **页大小上限 20** |

## 三、解决方案（0.3.11 已实现）

### 3.1 播放：修 Cookie 形态 + 补齐网页端请求头

```js
function getCookieString() {
  ...
  // 分隔符必须是 "; "（分号 + 空格）。真实浏览器一律带空格，
  // 实测 playurl 对 "a=1;b=2" 直接 412（6/6），换成 "a=1; b=2" 后 0/6。
  return parts.join("; ");
}
```

```js
const res = await axios.get("https://api.bilibili.com/x/player/playurl", {
  headers: {
    ...headers,
    referer: "https://www.bilibili.com/",   // 0.3.11 补：PiliPlus 每次播放都带
    origin: "https://www.bilibili.com",
    cookie: getCookieString(),
  },
  params,   // { bvid|aid, cid, fnval: 16 } (+ try_look=1 重试时)
});
```

顺带说明：**不需要**给 playurl 加 WBI 签名。原插件注释里「wbi/playurl + gaia 参数实测持续 412」的结论，实际上是撞在 Cookie 格式上；本次实测不签名版 6/6 全通。

### 3.2 列表：App 接口为主，网页接口兜底

- 主路径 `app.bilibili.com/x/v2/space/archive/cursor`，`appkey + ts + MD5(query+appsec)` 签名，不带 cookie。
- 按 `mid` 缓存「第 p 页之后该用的 aid」，正常顺序翻页零额外请求；跳页逐页补齐（上限 20 页），补不齐落网页兜底。
- 网页兜底补齐 `buvid4` / `buvid_fp` / `CURRENT_FNVAL`、浏览器指纹头、`; ` cookie；412 时换 buvid3 重试一次。
- 顺带修掉：`accept-encoding` 声明 `br`（宿主只解 gzip）、作者作品 `duration` 恒为 0、把 `first_cid` 带下去省一次 `view` 请求。

### 3.3 与 PiliPlus 播放逻辑的对照

| 维度 | PiliPlus | 插件 0.3.11 |
| --- | --- | --- |
| 接口 | `/x/player/wbi/playurl`（WBI 签名，`Api.ugcUrl`） | `/x/player/playurl`（不签名，实测可用） |
| Cookie | cookieJar → **`join('; ')`** | `getCookieString()` → **`join('; ')`** ✅ |
| 参数 | `fnval=4048`、`qn=80`、`fourk=1`、`fnver=0`、`gaia_source=pre-load`、`isGaiaAvoided`、`web_location=1315873`、`dm_img_*` | `bvid|aid` + `cid` + `fnval=16` |
| referer | `https://www.bilibili.com` | 同 ✅ |
| 未登录 | `try_look=1` | 拿不到流时 `try_look=1` ✅ |
| 音流选择 | dash → 按 quality 取 | dash.audio 按 bandwidth 排序后取 ✅ |

> 若将来 `playurl` 也开始随机采样 412，两条升级路径：① 切 PiliPlus 的 wbi 形态（参数见上表）；② 用 App 端 gRPC `bilibili.app.listener.v1.Listener/PlayURL`（`lib/grpc/audio.dart`，专为「音乐模式」设计，最贴合本场景，但需要在插件里实现 protobuf 编解码，本次未做）。

## 五、风险与回归清单

| 风险 | 说明 | 处理 |
| --- | --- | --- |
| appkey 失效 | `dfca71928277209b` 为 PiliPlus 在用 Android key，B 站换 key 会一起挂 | 兜底走网页接口 |
| 页大小 30 → 20 | App 接口 `ps` 上限 20 | 与 MusicFree `pageSize=20` 一致，`isEnd` 用 `has_next` 判断，不漏尾页 |
| 跳页成本 | 直接请求第 N 页需补齐 1..N-1 游标 | 上限 20 页，超出落网页兜底 |
| 内存 | `arcChains` 每 mid 一个数组 | 200 条上限 + 最旧淘汰 |
| 充电专属 | 网页 `is_charging_arc` vs App `is_ugcpay` | 已映射为 `vipExclusive` |
| 多 P 视频 | `first_cid` 只是第一 P | 与旧行为一致（旧代码走 `view` 拿到的也是第一 P） |
| 其它网页接口 | `view`（`getCid`）同样在网页风控面 | 列表已带 `cid`，正常路径不再调用；未登录场景仍可能被采样 |
