# 音源音质声明 · 数据源自动换源 改造计划

> 目标：插件声明播放/下载音质 → 界面只显示真实可用档位；数据源自动管理同平台播放源列表并支持失败自动切换；插件状态变化实时同步到播放/搜索界面。

---

## 0. 现状与差距

| 需求 | 现状 | 差距 |
|---|---|---|
| 1 插件声明播放/下载音质、登录态 | `sources[x].qualitys` 单一声明；无下载音质、无登录态、无凭据输入 | 需扩展插件协议 + 新增凭据存储/注入/检测 |
| 2 界面按声明显示音质 | `MusicSourceManager.getSupportedQualitiesForSourceId` 优先用插件声明的 `qualities`，**为空时回退平台默认全档位**（`_defaultQualities`，wy 有 6 档、tx 有 7 档）；下载菜单复用同一个列表 | 下载/播放分离；未声明的老插件仍会显示全档位 |
| 3 数据源播放源管理 | `dataSourcePlaybackSourcesProvider` 是 `Map<pluginId, sourceId>` 单选，用户手动在"设置播放源"下拉里挑 | 改为**自动发现的同平台播放源有序列表**，按安装时间排序、可拖动、取第一个优先 |
| 4 数据源自动换源 | `_resolveViaDataSourcePlayback` 只用 1 个播放源，失败直接抛 `DataSourcePlaybackException`；控制器对数据源失败"重试没有意义"直接停 | 按列表逐个尝试，每个源 10s 超时，全部失败才停，并汇总原因 |
| 5 MF 禁止自动换源 | `getMusicUrlResultCandidates` 对**所有**同平台 host 依次尝试（含多个 MF 插件） | 非数据源需收敛为"只用选定的那个插件" |
| 6 实时同步 | 安装/卸载 → invalidate `pluginInitializedProvider` + `pluginsProvider`；音源开关 → invalidate `pluginSupportedSourcesProvider`；搜索页 watch `searchAvailableSourcesProvider`（会刷新） | 播放中的 `state.availableQualities` 只在 `playSongAt` 时算一次，插件变化后不重算；当前歌曲的源失效无提示 |

关键代码位置：

- `lib/features/plugin/application/music_source_manager.dart`
  - `getSupportedQualitiesForSourceId` (430)、`_defaultQualities` (460)
  - `_resolveViaDataSourcePlayback` (1789)、`getMusicUrlResultCandidates` (1694)
  - `playbackFallbackSourceIds` (2203)、`getMusicUrlForDownload` (2164)
  - `dataSourcePlaybackSources` 映射 (702-712)
- `lib/features/plugin/data/plugin_host.dart`：`_parseSourcesWithActions` (422)、导出解析 (241)
- `lib/features/plugin/data/lx_plugin_converter.dart`：`__lxNormalizeSources` (136)、`mockLx` (386)
- `lib/features/player/application/playback_controller.dart`：解析 (511)、播放 (960)、`setQuality` (1593)、错误监听 (1888)
- `lib/features/settings/presentation/plugin_management_page.dart`：数据源卡片 `_buildDataSourcePlaybackRow` (761)
- UI 音质入口：`player_controls.dart:81`、`song_action_sheet.dart:229`、`download_providers.dart:106`

## 1. 插件协议扩展（向后兼容，缺省行为不变）

### 1.1 LX 插件 `sources[x]` 新字段

```js
const sources = {
  wy: {
    name: '网易云音乐',
    type: 'music',
    actions: ['musicUrl', 'loginStatus'],   // loginStatus 可选：支持被主动查询登录态
    qualitys: ['128k', '320k', 'flac', 'flac24bit'],      // 【语义固定】播放音质
    downloadQualitys: ['128k', '320k', 'flac'],           // 新增，缺省 = qualitys
    login: {                                              // 新增，可选
      required: true,                 // 高音质是否依赖登录
      freeQualitys: ['128k', '320k'], // 未登录仍可用的档位，缺省 = qualitys
      state: 'loggedOut',             // loggedIn | loggedOut | unknown | expired，缺省 unknown
    },
    credentials: [                    // 新增，可选：需要用户填写的凭据
      { key: 'MUSIC_U', label: 'MUSIC_U', secret: true,
        hint: '浏览器登录 music.163.com → F12 → Cookie 复制 MUSIC_U' },
    ],
  },
};
```

### 1.2 凭据注入（插件侧读取方式）

```js
const vars = (typeof lx.getUserVariables === 'function' && lx.getUserVariables()) || {};
const cookie = vars.MUSIC_U || '';
```

宿主同时提供：
- `lx.getUserVariables()` → `{[key]: value}`
- `lx.currentScriptInfo.userVariables` → 同一份
- 保留现有 `lx.currentScriptInfo.rawScript`（老插件用头部注释正则取值的写法继续可用）

### 1.3 登录态上报（三种，优先级从高到低）

1. **主动查询 action**：`actions` 含 `loginStatus` 时，App 调用
   `request({ source, action:'loginStatus', info:{} })`，插件返回
   `{ state:'loggedIn'|'loggedOut'|'expired', account?, message? }`
2. **运行时事件**：`lx.send('loginStatus', { source, state, account?, message? })`
3. **静态声明**：`sources[x].login.state`

`__lxNormalizeSources` 需要放行 `loginStatus` 事件（当前只接受 `inited` / `updateAlert`，其它一律 reject）。

### 1.4 兼容策略

- 老插件（无新字段）：`downloadQualitys` 取 `qualitys`；`login` 视为 unknown，不做登录门槛过滤；界面行为与现在一致。
- MusicFree 插件：声明在 `musicItem.qualities`（每首歌），本次不改；下载音质 = 播放音质。

## 4. MusicSourceManager 改动

### 4.1 音质查询（需求 1/2）

```dart
enum QualityUsage { play, download }

List<String> getQualitiesForSourceId(String sourceId, {QualityUsage usage = QualityUsage.play});
List<String> getDownloadQualitiesForSourceId(String sourceId);

/// 未登录/登录失效时不可用的档位（用于菜单标灰）
Set<String> getLoginGatedQualities(String sourceId);

/// 数据源歌曲：实际生效的播放源（用于取对应音质列表）
String? effectivePlaybackSourceForSong(Song song);
```

规则：
1. 解析到具体插件（`平台id@插件id`）→ 用该插件源声明；
2. 插件未声明 → 回退 `_defaultQualities`（保持现状，不引入回归），但在 UI 上标注"音源未声明音质"；
3. `usage == download` 时优先 `downloadQualitys`；
4. 数据源歌曲：先确定"第一个可用播放源"，取其声明；未确定 → 用平台默认。

`getSupportedQualitiesForSourceId` 保留为 `getQualitiesForSourceId` 的别名（减少调用点改动）。

### 4.2 数据源播放源列表（需求 3）

```dart
// 旧: Map<String, String>            pluginId -> sourceId
// 新: Map<String, List<String>>      pluginId -> 有序候选
Map<String, List<String>> get dataSourcePlaybackSources;
void setDataSourcePlaybackSources(Map<String, List<String>> map);

List<String> dataSourcePlaybackSourcesFor(String pluginId);      // 有效（存活的）列表
List<String> autoDiscoverPlaybackSourcesFor(String pluginId);    // 自动发现，按安装时间升序
```

自动发现规则：
- 取该数据源支持的平台 id 集合（`host.sources` → `SourceIdMapping.deriveId`）；
- 遍历所有 `isEnabled && !isDataSource && 能解析地址(actions 含 musicUrl)` 的插件；
- 对每个交集平台产出 `平台id@插件id`；
- 排序：`PluginInfo.installTime` 升序（需要 `PluginService` 暴露 `installTimeOf(pluginId)`）；
- 用户在 UI 里手动排过的顺序覆盖自动顺序，持久化在 `dataSourcePlaybackSources`。

过滤：已卸载 / 已关闭插件 / 已关闭音源（`isPluginSourceEnabled`）自动剔除；播放时若列表为空 → 即时用 `autoDiscover` 兜底一次。

### 4.3 迁移

`settings_providers._decodeDataSourcePlaybackSources`：兼容三种历史格式
- `{"pid": "wy@xxx"}` → `{"pid": ["wy@xxx"]}`
- `{"pid": ["a","b"]}` → 原样
- 空 / 非法 → `{}`，解析失败不抛异常，打印一次日志。

### 4.4 数据源多源自动切换（需求 4）

新增：

```dart
class DataSourceResolveOutcome {
  final PluginMusicUrlResult result;
  final String playbackSourceId;      // 实际成功的播放源
  final List<DataSourceAttempt> attempts; // 每个源的失败原因 + 耗时
}

Future<DataSourceResolveOutcome> resolveViaDataSource(
  Song song, {
  required String quality,
  Set<String> excludedUrls = const {},
  Set<String> excludedSources = const {},          // 本次播放已失败的播放源
  Duration perSourceTimeout = const Duration(seconds: 10),
  void Function(DataSourceAttempt attempt)? onAttempt,
  void Function(String message)? onResolveError,
});
```

执行流程（每个播放源）：

```
for source in 有序列表 (跳过 excludedSources):
    deadline = 10s
    try {
      withTimeout(deadline):
        1) 同平台：直接用 song.id 构造 musicInfo（不搜索）
           跨平台：search(song.title + artist) → _isSameSong / _bestTitleMatch
           搜索耗时计入同一个 10s 预算
        2) 调该插件 musicUrl(quality)
        3) 校验：URL 合法、非酷我提示音、音质匹配
      → 成功：记录 attempt(ok)，返回 outcome
    } on TimeoutException → attempt(超时)，继续下一个
    on 其它异常 → attempt(错误摘要)，继续下一个
全部失败 → 抛 DataSourcePlaybackException(汇总文案)
```

错误文案（每条最多 60 字，最多列 3 条，其余用"等 N 个"）：

```
此网易云数据源没有可用的播放源（已尝试 3 个）：
 · 网易云官方：登录已失效，无法获取无损
 · XX音源：请求超时（10 秒）
 · YY音源：该音源不支持 flac，实际只提供 320k
请在插件管理中检查播放源顺序或凭据。
```

**关键点**：跨平台搜索失败也算该源失败，不能中断整条链。

### 4.5 非数据源禁止自动换源（需求 5）

`getMusicUrlResultCandidates` 增加 `bool allowMultiHost`：

- 歌曲 `source` 带具体插件（`平台id@插件id`）→ **只试该插件**，不遍历其它 host；
- 歌曲是裸平台 id → 按"优先音源 → 安装顺序"选**第一个**可用插件，只试它；
- 唯一例外保留：该插件**已不存在**（卸载/重装换 id）时，允许用同平台存活插件兜底（这是容错，不是换源）；
- 数据源路径不走这里（走 4.4）。

## 5. 播放控制器改动

### 5.1 数据源换源（需求 4）

- 新增 `Map<String, Set<String>> _failedPlaybackSources`（key = `song.id|source`），换歌 / 手动重播时清理。
- `playSongAt` 的取地址失败分支、`setAudioSource` 失败分支、`_mountOneTimeErrorListener` 中途中断分支，统一走：

```dart
if (manager.isDataSourceSource(song.source)) {
   // 数据源：拿下一个播放源
   outcome = await manager.resolveViaDataSource(song,
       quality: q, excludedSources: _failedFor(song), onAttempt: ...);
   // 成功 → setAudioSource + resume；失败 → 停止播放 + 汇总提示
} else {
   // 非数据源：按 4.5 只重取原源 URL（现有逻辑），不再跨源
}
```

- 超时：`_dataSourceSourceTimeout = 10s`/源；`_urlFetchTimeout`(50s) 仅在数据源整体外层兜底。
- 进度提示：`onMessage` 显示 `tr('播放源 1/3 失败，正在尝试「网易云官方」…')`，避免用户以为卡死。
- 每个播放源的失败要**串行**，不能并发（避免同时打多个插件、也避免地址串台）。

### 5.2 音质切换（需求 1/2）

- `setQuality(quality)`：先校验目标音质 ∈ 当前播放音质列表，否则拒绝并提示"该音源不支持 X"。
- 请求的是登录受限档位且未登录 → 直接提示"需要先在插件管理里填写凭据"，不发请求。
- 数据源歌曲换源后音质不变（不降级）。

### 5.3 实时同步（需求 6）

- `ref.listen` 监听：`pluginsProvider`（增删改）、`pluginSupportedSourcesProvider`、`pluginSourceStateProvider`、`dataSourcePlaybackSourcesProvider`。
- 回调里调 `PlaybackController.refreshAvailability()`：
  - 重算 `state.availableQualities`（当前歌曲对应源的最新档位）；
  - 若当前音质已不在列表里（插件关闭导致）→ 保留播放，提示"当前音源已停用 X 音质，切歌后生效"，**不打断正在播放的音频**；
  - 若当前歌曲的源插件已卸载 → 提示"该音源已卸载"，不自动切源（数据源除外：数据源按列表自动续）。
- `dataSourcePlaybackSourcesProvider` 变化 → 清 `_failedPlaybackSources`（顺序变了，之前的失败记录作废）。

## 7. 异常处理矩阵

| 场景 | 期望行为 |
|---|---|
| 插件 `musicUrl` 抛错 | 该播放源记失败（错误摘要），继续下一个（数据源）；非数据源停止并提示原错误 |
| 插件返回空 / 非 http URL | 视为该源失败，不写入队列 |
| 插件返回音质低于请求 | 拒绝该地址（现有逻辑），提示"实际只提供 X"，换下一个源 |
| 插件返回酷我提示音 | 现有 `_isKuwoPromptUrl` 拦截，继续下一个 |
| 单个播放源 > 10s | `TimeoutException` → 记"超时"→ 继续下一个（不重试同一源） |
| 所有播放源失败 | 停止播放，一次性汇总提示（最多 3 条明细），不自动跳下一首 |
| 数据源未配置任何播放源 | 即时 `autoDiscover` 一次；仍为空 → 明确提示安装/启用插件 |
| 数据源播放源列表全是失效插件 | 剔除后为空 → 同上提示，不抛未捕获异常 |
| 用户未填凭据 | 高音质档位置灰 + 点击提示；不强发请求 |
| 凭据错误 / 登录过期 | 插件返回 401/403 或 `expired` → 自动把该源标记 `expired`（徽标变红），继续下一个播放源 |
| `loginStatus` action 超时/抛错 | 登录态保持 unknown，不影响播放，不弹错误 |
| 搜索不到歌（跨平台换源） | 该源记"没搜到这首歌"，继续下一个 |
| 播放中途 URL 过期 | 先重取当前源（一次），再按顺序尝试下一个源（数据源） |
| 播放中途插件被关闭 | 提示"音源已停用"，保留当前音频，不打断；下次播放按新状态选源 |
| 插件排序时插件被卸载 | 保存前过滤失效 id；保存失败回滚到上一份顺序 |
| `plugins.json` 旧格式 | `fromJson` 缺字段走默认值，不抛异常 |
| 设置里旧格式播放源映射 | 迁移为单元素列表，失败则丢弃该项并记日志 |
| 注入凭据含非 ASCII / 换行 | 注入前清理控制字符，避免 JS 字符串转义错误；值本身允许中文 |
| 用户变量为空对象 | `getUserVariables()` 返回 `{}`，插件侧 `vars.MUSIC_U || ''` 安全 |

## 10. 已确认的 3 个决策

1. **非数据源一律禁止跨插件换源**（MF 与 LX 同等对待）。
   - 只使用歌曲绑定的那个插件，或裸平台 id 按"优先音源 → 安装顺序"选中的第一个插件；
   - 唯一保留的容错：该插件已被卸载/重装换 id 时，允许同平台存活插件顶上（属于"找不到原插件"，不是换源）。
   - 影响：`getMusicUrlResultCandidates` 的 `allowMultiHost` 默认 `false`，只有数据源路径（4.4）与"插件已失效"兜底会遍历多个源。

2. **需要登录的高音质：显示但置灰**。
   - 菜单项保留，副标题 `需登录`，点击弹提示「请先在插件管理 → 该插件 → 凭据 里填写 xxx」；
   - 不隐藏的理由：用户能知道"有这一档、只是缺登录"，不会误判音源不支持；
   - 下载菜单同理（置灰 + 提示），避免下载时静默降级。

3. **凭据跟随设置一起备份**（`SharedPreferences` / `settingsService`，随 WebDAV 与本地备份导出）。
   - 实现：`settingsService.setPluginCredentials(jsonEncode(...))`，key `plugin_credentials`；
   - **风险提示（需在 UI 明示）**：备份文件里会是明文 cookie，插件管理页凭据区固定显示一行小字
     「凭据会包含在备份文件中，请勿分享备份」；
   - 导出备份时不做剔除；恢复备份时与插件列表按 `pluginId` 合并，插件已不存在则保留（重装后同 id 才生效，否则由用户重填）。

## 11. 风险

- **改动面大**：跨 10+ 文件，`plugin_management_page.dart`（2166 行）与 `music_source_manager.dart`（3226 行）都要动，回归风险集中在"播放失败路径"。
- **性能**：数据源 3 个源 × 10s 最坏 30s，必须有逐步提示，否则体感是卡死。
- **插件生态**：新字段是我们自己的约定，官方落雪没有 `downloadQualitys`；需要在 `docs/lx_source_adaptation.md` 写清楚，避免插件作者困惑。
- **登录态检测**：只有实现了 `loginStatus` 的插件能真正检测；其余只能显示 unknown，不能假装"已登录"。
- **凭据明文随备份**：用户已确认凭据跟随备份导出，备份文件里是明文 cookie。除 UI 警示外，README / 备份说明里补一句提醒；恢复备份时不要打印凭据内容到日志。

## 13. 追加需求：只认落雪格式 + 音源健康红标（2026-10-31）

### 13.1 自动发现 / 自动换源只接受落雪（lx）格式

用户明确：**「必须是落雪格式解析源，MusicFree 格式不支持」**。

- `MusicSourceManager.isPlaybackSourcePluginFormat(pluginId)` → 只放行 `_pluginTypes[pluginId] == 'lx'`；
- `autoDiscoverPlaybackSourcesFor` 遍历时跳过非 lx 插件；
- `dataSourcePlaybackSourcesFor` 过滤**历史配置**（旧版本可能存了 MF / 澜音 源）；
- 新增 `isAutoSwitchEligible(sourceId)` = 插件存活 + 有 musicUrl + 落雪格式，
  插件管理页重排时用它剔除失效 / 非 lx 条目；
- `_resolveWithPlaybackSource` 里再兜一层：拿到非 lx 源直接抛
  「该音源不是落雪格式，不能作为数据源的播放源」。

> 澜音（cr）同样被排除：它和 MusicFree 一样是全功能音源，不是纯解析源。
